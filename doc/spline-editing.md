# 保存したB-spline・NURBSの再編集

2026-11-16に、既存曲線を元の制御点から再計算する編集画面を追加しました。対象は、このエディタで生成し、`data-vector-spline` を保持したB-spline・NURBSです。SVG保存・再読込後にも利用できます。計算119機能・GUI31ツールは変更していません。

## 操作

選択ツールで曲線を1個選び、ツールプロパティの「曲線の元データを編集」から「曲線を再編集」を押します。画面に番号付きの制御点と灰色の破線の制御多角形が表示され、制御点をドラッグできます。座標欄では1行に `x, y` を入力できます。これは図形のローカル座標で、既存の移動・回転・拡縮を取り除いた座標です。親グループの変換も保持します。

次数、周期指定、ノット列、NURBSの重み、描画分割数を編集できます。NURBSでは分母の除外幅・検査深さ・処理上限も変更できます。制御点数は次数より多く、最大1000点、次数は1〜12です。ノットを空欄にすると開いた曲線用のクランプノットを自動生成し、重みを空欄にすると全て1にします。「ノットを自動生成」も使えます。点数や次数を変更した場合、手入力のノット列・重みの要素数も合わせてください。

周期曲線は元の制御点と重みだけを表示し、末尾に循環用として追加された点は表示しません。適用するたびに循環用の点が増えることはありません。周期指定時は一様ノットを自動生成し、ノット欄を隠します。

「プレビュー」は青い破線を重ねます。元図形は変更せず、プレビュー中にSVG保存しても元図形だけを保存します。「適用」は同じSVG要素の形状と計算・描画記録を更新し、1回のUndoで元に戻せます。Redoで編集後へ戻せます。「取消」、選択対象の変更、別ツールへの切替では未適用の入力とプレビューを破棄します。

ID、親グループ、レイヤー、変換、色、線幅、線種を保持します。ただし、分母零付近などを省略した部分描画では、開いた枝を塗りで結ばないように塗りをなしにします。省略区間と処理上限は従来どおり記録し、プロパティにも警告を表示します。後で全区間を描画できても、以前の塗りを自動復元する処理はありません。

## 制御点のドラッグ

制御点をつかんで移動すると、座標欄と青い破線の曲線プレビューを更新します。元図形は「適用」まで変更しません。つかんだ位置と制御点の中心のずれを保持し、ハンドルの端を押したときに点が飛ばないようにします。2画面ピクセル未満の移動はクリックとして扱います。クリックだけでグリッドへ移動することはありません。

親グループの移動・回転、図形の回転・反転・縦横別の拡縮、画面のズーム・パンに対応します。制御点のハンドルは画面上で一定の大きさを保ちます。再編集している間は通常の図形全体の変形ハンドルを隠し、取消・適用後に選択ハンドルへ戻します。

グリッドスナップは図面座標で行います。Shiftを押すか直交モードをONにすると、移動開始点を基準に図面の横軸・縦軸に沿って動きます。両方を使う場合はグリッドへ合わせた後で軸方向を制限するため、固定側の座標は移動開始点の値を保ちます。標準ホストでは、この制御点移動に端点・中点・交点などへの幾何スナップは適用しません。

ドラッグ中にEscを押す、ポインター操作が取り消される、ウィンドウがフォーカスを失う場合は、そのドラッグを始める直前の座標へ戻します。それ以前の未適用の編集は保持します。ドラッグしていない状態でEscを押すと再編集全体を取り消します。入力欄にフォーカスがある場合のEscはこの操作の対象外です。マウスをキャンバス外で離しても最後の位置を処理します。別ツールへの切替・選択変更ではドラッグと未適用の編集を破棄します。

周期曲線のハンドルは元の制御点だけです。先頭点を動かすと評価用の循環点も再生成し、同じ点のハンドルが重複することはありません。零・負の重み、分離された枝、省略区間の警告は数値入力での再編集と共通です。

ロック・非表示・削除・選択変更、または元の形状が編集中に変更された場合は移動を停止し、元図形を上書きしません。拡縮率0など逆変換できない図形ではハンドルを表示せず、理由を表示します。座標欄による入力は引き続き使えます。

制御多角形・ハンドル・番号・プレビューはSVG保存、PNG出力、Undo履歴に含めません。何度点を動かしても、「適用」までは図面の履歴を追加せず、「適用」1回がUndoの1段階になります。

## 使用実装とアルゴリズム

再編集欄の「再計算の実装」「再描画の実装」に、その曲線に記録された実装とアルゴリズムを表示します。登録済みの対応実装へ切り替えて再計算できます。記録されたIDが現在未登録なら明示し、適用を拒否します。別の実装を使う場合は選択し直します。SVGから実装コードを読み込んで実行する機能はありません。

この選択は対象図形の再編集に使います。次の作図用に選択した計算・描画方式や、その描画設定は変更しません。標準のB-spline・NURBSには現時点で複数の計算方式は登録されていませんが、既存の換装APIで追加した方式もここから選択できます。再編集結果には、元モデルを持つSVG `path` を返す必要があります。

標準計算は [splineCurves.js](../src/model/splineCurves.js) の入力検証と周期構成、標準描画は同次de Boorの極形式による区間ベジェ化、Bernstein係数による分母範囲判定、de Casteljau再分割、パラメータ等分割によるSVG折れ線です。手順と実装時参照資料は [spline-branches.md](spline-branches.md#実装時に参照した一次資料)にあります。今回の編集UIに新しい幾何アルゴリズムや別の論文実装を追加したわけではありません。

## 元データと現在の形状の照合

新規作図・再編集では、`data-vector-spline` に `{version:1, model:..., path:...}` を保存します。`path` は出力したSVGの `d` 属性の文字列です。再編集を開始する際、モデルの妥当性に加えて、この文字列と現在の `d` が一致することを確認します。これは改ざん検証用の署名ではなく、輪郭編集などで古くなったモデルから別の形状へ戻すことを防ぐ照合情報です。属性値を同時に外部編集した場合の真正性は保証しません。

PR #53の旧形式 `{version:1, model:...}` も読み込めます。標準描画で保存された設定から形状を再生成し、現在の `d` と一致する場合だけ再編集を許可します。形状文字列が外部ソフトで書き換えられた場合は、見た目が同じでも拒否することがあります。旧形式の外部描画には照合情報がないため、この再編集は提供しません。

不正な入力、描画できる区間がない結果、未登録実装では元図形を変更しません。編集中に対象の形状・元モデルが変わった場合や、対象が削除・ロック・非表示になった場合も適用を拒否します。取消後に対象を確認して読み直してください。

トリム・分割・延長によって生成済みの折れ線を直接編集した場合、元スプラインのモデルがその輪郭を表さなくなるため、`data-vector-spline` と部分描画マーカーを取り除きます。その図形は通常のパスとして扱い、この再編集欄は表示しません。既存の生成方式の記録は元モデルとは別です。

## コードとAPI

ドラッグ操作と補助表示は [SplineControlHandles.js](../src/ui/SplineControlHandles.js)、画面・図面・図形ローカル座標の相互変換は [splineControlGeometry.js](../src/adapters/splineControlGeometry.js)です。座標計算は既存の [affine.js](../src/model/affine.js) の行列合成・逆行列・点変換を使用します。描画前の曲線計算は従来のde Boor・Bernstein範囲判定・de Casteljau分割を再利用します。

ポインター移動は描画フレームごとにまとめ、離した位置は待機中の更新より優先して直ちに反映します。編集中の図形・ビューの変換を監視して補助表示を更新し、終了時に監視・ポインター取得・イベント処理を解除します。標準ホストのスナップ経路は `host.snap(point, {geometry:false, exclude:element, anchor, manager})` で、独自ホストではこの契約に対応したスナップ関数を提供できます。

UIと適用処理は [SplineEditor.js](../src/ui/SplineEditor.js)、保存モデルの読込・検証は [splineSource.js](../src/adapters/splineSource.js)、パネルへの組込は [ToolPropertiesPanel.js](../src/ui/ToolPropertiesPanel.js)です。`readSplineSource(sourceText, implementationText, currentPath)` は、元入力、使用方式ID、描画設定を返し、不正・不一致を例外で通知します。

[editorHost.js](../src/adapters/editorHost.js) の `host.render(shape, null, {toolName:'nurbsCurve', renderer:'default', sampleCount:120})` は、今回の呼出しだけに描画実装・設定を指定できます。`renderer` を省略した従来の呼出しは、引き続きツールごとの選択設定を使います。`host.describeRendering(name, rendererId)` は指定した方式の説明を返します。

`renderer` を明示した場合、その呼出しの設定を使い、別の作図用に保持した設定を上書きしません。外部描画関数そのものを `render` として差し替えたホストでは、引き続きその関数の契約に従います。
