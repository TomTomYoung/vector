# フィレットの元データ保存・再編集

更新日: 2026-11-16（日本時間）。フィレットの円弧と両側の線分を、保存した作図前の2線分・半径からまとめて再計算します。

## 操作

フィレットツールで2本の線分を選ぶと、作図前の端点座標、半径、計算結果、作図後の円弧と2線分の対応を保存します。選択ツールで円弧を選び、ツールプロパティの「フィレットの元データを編集」から「フィレットを再編集」を押します。

半径、計算実装、描画実装、描画分割数を指定できます。元の2線分の座標は読取専用で表示します。プレビューは円弧と両側の線分の3要素を青い破線で表示し、「適用」で接点と円弧を同時に更新します。半径を小さくすると、一度切り詰めた線分を元の作図入力に基づいて伸ばし直します。取消・Esc・ツール切替では未適用の変更を破棄します。半径ハンドルによるドラッグに対応しています。元の線分の端点をドラッグして入力を変更する操作は未導入です。

標準SVG円弧・等分割折れ線・三次ベジェ近似を切り替えられます。プロパティには使用する計算・描画のアルゴリズム、半径、元の線分と元の生成方式を表示します。円弧を折れ線や三次ベジェに変更しても、両側の線分はSVG `line` のままで、その描画方式を個別に記録します。各方式の選択は編集対象にだけ適用し、次の作図用の設定を変えません。

## 半径ハンドル

「フィレットを再編集」で第一線分の接点に半径ハンドルを表示します。元の角から接点への補助線も表示し、ハンドルをドラッグすると半径欄と円弧・両側の線分のプレビューを更新します。反転・せん断・縦横別拡縮・親グループ・ズームを扱い、ハンドルは画面上で一定の大きさです。半径を変えると中心も動くため、以前の円の中心からの距離を半径として使いません。

角の交点を V、第一線分の単位方向を u、内角を θ として、ハンドル位置は `V + u * r / tan(θ / 2)` です。ポインターをローカル座標へ戻し、つかんだ位置のずれを補正し、グリッド・Shift・直交モードを図面座標で適用してから第一線分の方向へ投影します。投影距離に `tan(θ / 2)` を掛けて半径を求めます。グリッド点を投影するため、斜めの線分では最終ハンドル位置がグリッド点そのものになるとは限りません。

クリックのみでは半径を変えません。ポインターの最後の位置を反映し、キャンバス外での終了にも対応します。ドラッグ中のEsc・ポインター取消・取得喪失・フォーカス喪失は、そのドラッグ開始前の半径へ戻します。先に入力した数値編集は残します。それ以外のEscは再編集全体を取り消します。図形と履歴は適用まで変更せず、補助表示を保存しません。適用後のUndo/Redoは円弧と両側の線分をまとめて扱います。

参照線分の変更・削除・ロック、形状や相対変形の不一致、非可逆な変換ではドラッグを停止します。半径が非正・非有限になる移動や計算・描画の失敗は、そのドラッグを戻します。数値を修正したり変換を戻したりすると、条件を満たす場合はハンドルを再表示します。パン操作・別ポインターを優先または無視し、選択・ツール変更時は監視とポインター取得を解除します。

ハンドルの逆算は2直線への標準の接線構成に対応します。選択した計算実装が返す第一接点がこの構成と一致することを確認して表示します。異なる接点規則の外部実装や、ハンドル位置を数値精度で表せない場合はハンドルを表示せず、数値欄によるプレビュー・適用を使います。計算実装の選択はハンドルの検査・ドラッグ失敗時にも元へ戻し、次の作図用の設定に影響しません。

座標と半径の対応は [filletControlGeometry.js](../src/adapters/filletControlGeometry.js)、操作は [FilletRadiusHandle.js](../src/ui/FilletRadiusHandle.js) です。半角の三角関数による既存の接線構成を逆に解いたもので、新しい名前付き計算法や継続的拘束ソルバーを導入したものではありません。

## 関連する3要素と座標

円弧のローカル座標で作図前の線分と半径を保持し、各線分の座標系から円弧の座標系への行列を保存します。親グループ・各線分の変形を含めて座標を変換するため、元から変形されている線分でも再編集できます。円弧と線分をまとめて共通のアフィン変換で移動・回転・拡縮した場合は、その変形を保って再計算します。縦横別拡縮後の画面上の円弧は楕円となり、指定半径はローカル座標の値です。

線分と円弧を別々に移動・変形した場合、線分の端点や計算記録が変わった場合、参照する線分が削除・非表示・ロックされた場合、参照IDが複製されて曖昧な場合は再編集を停止します。変形行列は浮動小数点の誤差を考慮して照合し、つぶれた変形を拒否します。円弧のパスと元データも照合します。元の要素を推測して付け替えることはありません。

3要素の再計算・描画・座標検査を終えてから図面を更新します。途中の計算エラー・未登録実装・非対応描画では、一部の線分だけを書き換えません。適用1回をUndoの1段階にまとめ、Redo・SVG保存と読込にも参照を引き継ぎます。色・線幅・線種・スタイル・変形・レイヤー・親内順序・子要素を保持し、補助表示は保存しません。

別のフィレットで同じ線分の端点を変更すると、以前のフィレットは保存時の形状との不一致として停止します。複数フィレット間の連鎖再計算や継続的な接線拘束は行いません。線分の分割・円弧の直接輪郭編集なども、それまでの入力モデルを維持する操作ではありません。折れ線として描いた円弧の分割では両方の結果から元データを除去します。元データを持たない旧SVGからの線分・半径の逆推定は未導入です。

## 計算・描画と参照資料

計算は既存の [construction.js](../src/model/construction.js) の `fillet` を使用します。2直線の交点と各辺の向きを求め、内角を θ、半径を r として、交点から接点までの距離を `r / tan(θ / 2)`、交点から中心までの距離を `r / sin(θ / 2)` で構成します。交点に近い側の端点を接点へ置き換えます。線分の有限な長さによる半径上限は設けず、計算結果によっては端点を延長・反転することがあります。元の端点の順序と近い側を選ぶ既存の規則を維持します。

これは2直線への円の接線構成で、今回新しい名前付きアルゴリズムを導入したものではありません。既存実装の文献との対応・参照履歴は [algorithms.md](algorithms.md)、円弧の等分割と三次ベジェ近似の資料・実装は [implementation-options.md](implementation-options.md) から参照できます。任意曲線同士のフィレットや、解析幾何カーネル・拘束ソルバーによる連続的な拘束維持とは区別します。

## 保存形式と換装契約

円弧の `data-vector-fillet` に `version: 1`、`input: {first, second, radius}`、`result: {segments, bridge}`、`bindings`、描画後の `path` を保存します。各線分の `data-vector-fillet-line-id` と `bindings[].id` を対応させ、`bindings` には線分の幾何属性、生成方式記録、円弧に対する相対変換行列を保持します。新規IDはUUIDとし、既存の一意なIDは再利用します。重複するIDが読み込まれた場合は停止します。

`data-vector-implementation` には計算・描画ID、アルゴリズム・ソース、依存先、半径と元の端点、任意の `filletEdit.origin` を保存します。再編集のたびに生成履歴を入れ子にしません。両側の線分の描画記録は `native-segment` であり、円弧の描画方式を線分へ流用しません。

既存の `registerImplementation('fillet', {id, label, algorithm, run})` で換装します。入力は `{first: [始点, 終点], second: [始点, 終点], radius}`、結果は `{segments: [更新後の第一線分, 更新後の第二線分], bridge: 円弧モデル}` です。有限な端点・正の半径、中心・端点・回転角の整合した円弧、両線分と円弧の接点の一致、指定半径と結果の一致を検査します。計算方式の一時切替は成功・失敗のどちらでも元へ戻します。

描画登録は既存の `registerRenderer` を使用し、`fillet` を対象に円弧からSVG `path` を返す実装を受け付けます。計算・描画・保存の準備と照合は [filletSource.js](../src/adapters/filletSource.js)、新規作図接続は [BaseTool.js](../src/core/BaseTool.js)、再編集UIは [FilletEditor.js](../src/ui/FilletEditor.js) です。
