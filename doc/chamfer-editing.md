# 面取りの元データ保存・再編集

更新日: 2026-11-16（日本時間）。面取り線と両側の線分を、作図前の2線分と独立した距離1・距離2からまとめて再計算します。

## 操作

面取りツールで2本の線分を選ぶと、元の端点・距離・計算結果・3要素の対応を保存します。選択ツールで面取り線を選び、ツールプロパティの「面取りの元データを編集」から「面取りを再編集」を押します。

距離1は最初に選んだ線分、距離2は次に選んだ線分について、元の角の交点から辺に沿って測った距離です。数値欄で個別に変更できます。両方とも有限な非負数とし、少なくとも一方は正にします。一方を0にすると、その側の接続点は元の角に戻ります。距離を小さくした場合は、保存してある作図前の線分から端点を戻します。切り詰めた現在の線分を新しい元入力として使いません。

プレビューでは面取り線と両側の線分を青い破線で表示し、「適用」で3要素を同時に更新します。取消・Esc・ツール変更・選択変更では未適用の編集を終了します。図形と履歴は適用まで変更せず、補助表示を保存しません。適用1回をUndoの1段階とし、Redo・SVG保存と読込に元入力と要素参照を引き継ぎます。

計算実装・描画実装の選択肢にアルゴリズム名を表示します。図形には使用した計算・描画ID、実装元、委譲先、距離と元の端点、最初の生成方式を記録します。両側の線分にも、その端点更新とSVG線分描画を区別して記録します。編集対象の方式を変更しても、次の作図用の方式設定は変えません。

## 座標と関連する線分

元の2線分は面取り線のローカル座標で保存します。各線分の座標系から面取り線の座標系への行列を保持し、親グループ・回転・反転・せん断・縦横別拡縮を含めて端点を変換します。3要素をまとめて共通の変換で移動・変形した場合は、その変換を保持して再計算できます。距離はローカル座標の値で、縦横別拡縮後の画面上の距離と一致するとは限りません。

面取り線と両側の線分を別々に変形した場合、端点・生成方式記録が変わった場合、参照先が削除・非表示・ロックされた場合、参照IDが重複した場合は更新しません。面取り線自身への参照や非可逆変換も拒否します。計算・描画・3要素の照合が成功してから書き換えるため、失敗した場合に一部の端点だけを変更しません。色・線幅・線種・スタイル・変形・レイヤー・親内順序・子要素・選択を保持します。

同じ線分を使って別の面取り・フィレットを作ると、その線分を参照する以前の作図は形状や方式の不一致として停止します。連鎖更新や継続的拘束を行う仕組みではありません。直接の線分分割などは元の作図入力を維持する操作ではなく、分割した面取り線の両方から元データを除去します。元入力のない過去のSVGから、角や距離を推定しません。

## 計算・描画と参照資料

既存の [construction.js](../src/model/construction.js) の `chamfer` を使用します。2直線の交点を求め、各線分で交点に近い端点の側を置き換える対象とします。交点から各辺の単位方向へ距離1・距離2だけ進んだ点を求め、両点を面取り線で結びます。線分の有限長による距離上限は設けず、指定値によっては端点の延長・反転が生じます。平行・近い退化配置に対する既存の交点判定の閾値や数値精度保証は変更していません。

描画は3本のSVG `line` で、画素化はブラウザーが担当します。今回の追加は元入力と要素参照を使った再編集であり、新しい名前付き計算法を導入したものではありません。既存の計算・描画と文献・参照履歴の対応は [algorithms.md](algorithms.md)、換装APIと他方式の統合条件は [implementation-options.md](implementation-options.md) から参照できます。

## 保存形式と換装契約

面取り線の `data-vector-chamfer` に `version: 1`、`input: {first, second, distance1, distance2}`、`result: {segments, bridge}`、`bindings`、描画後の `geometry: {x1, y1, x2, y2}` を保存します。両側の線分の `data-vector-chamfer-line-id` を `bindings[].id` と対応させ、端点属性・方式記録・相対変換を照合します。フィレットの既存の参照ID・保存形式を維持し、両方式の参照IDを混同しません。

`data-vector-implementation` に現在の計算・描画実装、`parameters.distance1 / distance2 / first / second` と任意の `chamferEdit.origin` を保存します。再編集を重ねても元の生成方式を入れ子に増やしません。

計算は `registerImplementation('chamfer', {id, label, algorithm, run})` で換装できます。入力は `{first: [始点, 終点], second: [始点, 終点], distance1, distance2}`、結果は `{segments: [更新後の第一線分, 更新後の第二線分], bridge: {kind: 'segment', start, end}}` です。入力距離・元線分、結果の有限性・長さのある面取り線・両側の接続点の一致を検査します。`null`・例外・未登録IDは適用しません。再計算の一時的な実装選択は成功・失敗のどちらでも元へ戻します。

描画は既存の `registerRenderer` で換装し、`chamfer` に対応してSVG `line` を返す実装を使用できます。標準の計算・描画実装はそれぞれ1種類です。別の面取り計算法を新規追加したわけではありません。任意のSVGパスやグループを返す実装は、この線分再編集契約の対象外として適用前に拒否します。外部描画設定は方式記録に保持し、各呼出しで引き継ぎます。

元入力・結果の検査と準備は [chamferSource.js](../src/adapters/chamferSource.js)、フィレットと共用する線分の照合・座標変換・一括更新は [cornerLineBindings.js](../src/adapters/cornerLineBindings.js)、UIは [ChamferEditor.js](../src/ui/ChamferEditor.js)、新規作図接続は [BaseTool.js](../src/core/BaseTool.js) と [ChamferTool.js](../src/tools/ChamferTool.js) です。

## 残る範囲

距離ハンドル、元線分端点の直接編集、距離の自動上限、距離・角度による別入力方式、複数の面取り・フィレットの連鎖更新、継続的拘束、任意曲線同士の面取り、SVGパスやグループへの描画換装、外部SVGからの作図入力復元は未導入です。
